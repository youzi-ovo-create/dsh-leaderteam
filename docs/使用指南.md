# LeaderTeam V2.2 使用指南（Linux & Windows）

本文介绍 LeaderTeam V2.2 在官方 DeepSeek Harness（已端到端验证版本：`0.2.2-rc.1` 与 `0.2.2-rc.5`）中的安装启动、Solo-Key 与多网关模型配置、异步治理机制、长工程资源护栏及常见排障方法。

---

## 一、安装与首次启动工作流

1. **安装标准插件包（`dsh.bundle`）**：
   - **Linux / Web CLI**：`dsh plugin --profile web add ./dsh-leaderteam-2.2.0.tgz`（随后运行 `dsh web` 启动界面，或通过 `scripts/headless-run.mjs` 非交互运行）；
   - **Windows Desktop**：`dsh plugin --profile desktop add ./dsh-leaderteam-2.2.0.tgz`（若曾用旧版 V2.1 `install-desktop.ps1` 写入过 profile 补丁，升级前先在仓库根目录执行 `node bin/lt-doctor.mjs --clean-legacy-patch` 自动备份并清理旧补丁；传统脚本部署说明见《[官方Desktop部署与恢复](官方Desktop部署与恢复.md)》）。
2. **模型凭据准备（二选一）**：
   - **Solo-Key 免网关启动**：在启动 DSH 前设置环境变量 `DEEPSEEK_API_KEY`（或 `DASHSCOPE_API_KEY`、`ZHIPU_API_KEY`、`OPENAI_API_KEY`），首次启动会自动在 `<DSH_HOME>/leaderteam/config/leaderteam.config.json` 初始化在役模型与备用降级链，并在 DSH 设置中自动创建对应 Provider。
   - **多模型网关 / 自定义路由**：通过界面侧栏控制台或 `leaderteam.local.json` 绑定本地 OpenAI 兼容网关（如 Magpie）或多厂商直连路由。
3. **新建团队会话并提交需求**：
   - 选择目标项目工作区目录；
   - 在会话预设中选择 **LeaderTeam**，确认当前会话模型与 `roles.leader` 匹配；
   - 直接用自然语言描述工程需求与验收标准——**无需手动拆分任务或逐个管理子代理**。
4. **自主施工与后台异步监督**：
   - 领队会先用 `team_plan(action="overview")` 建立全局概览，再按依赖关系定义阶段（`stage`）并**免等待直接通过 `team_dispatch` 并行派发执行成员**，或通过 `team_direct_exec` 完成工作区内的快速探查、测试运行与局部修补。
   - 双评审（`discussA` / `discussB`）在后台异步监督阶段契约与实际文件变更：单边建议作为非阻塞参考回注领队；仅当某侧上游不可用时保持待审并在恢复后自动补审，绝不把失败请求伪造为赞同。
   - 领队或成员单轮输出触及模型 `max-tokens` 时，系统自动保留完整上下文与已成功工具列表无缝原位续接。

## 二、内嵌控制台与模型配置

随时点击 **DSH 界面侧栏的 LeaderTeam 图标**打开内嵌控制台（或在终端运行 `node scripts/configure-models.mjs --serve --open`）：

- **一键探测上游模型**：自动读取上游 `/v1/models` 暴露的真实模型列表、上下文窗口（`contextWindow`）与最大输出（`maxTokens`）。
- **角色与执行池独立配置**：
  - 独立配置 `leader`（领队）、`gate`（安全门）、`discussA` / `discussB`（双评审）、`arbiter`（独立裁断）、`serialReviewer`（串行证明复核）、`directExec`（直属执行）的模型路由、推理档位与 `fallback` 自动降级链。
  - 自由勾选普通成员候选执行池（`team.executionPool`）。
  - **热生效边界**：成员执行池、模型能力说明、并发上限与 `powerMonitor` 电量保护开关修改后立即生效；固定治理角色与安全策略按团队会话冻结，对新建会话生效。
- **实时调整最大并发数**：
  - 在团队会话中直接发送一行 `最大并发 4`（仅对当前会话立即生效，不打断在途成员、不推进任务序号）；
  - 或运行 `node scripts/dev/set-max-members.mjs --max 6` 调整全局默认上限。

## 三、争议裁断、长跑护栏与人工介入说明

正常工程推进全程自治。仅当触发以下治理或资源保护条件时，系统会有序介入：

1. **正式二方裁断会商（系统自动处理）**：
   - 当双评审对同一阶段一致提出强制干预异议，且「双评审 + 独立裁断」三方预议达到 2/3 多数时，系统先向在途执行成员发出即时交接检查点屏障使其安全暂停，随后开启「独立裁断 ↔ 领队」正式会商，并强制验证后续整改实质落地。
2. **5 小时请求窗口节流与笔记本低电量收尾**：
   - **5 小时窗口三级保护**：按上游 Provider 统计滚动 5 小时调用与配额快照，依次执行「抑制非必要探针 → 收紧新派发并发 → 检查点暂停新派发（`checkpoint_pause`）」，**全程绝不跳过安全门与双审**。
   - **低电量优雅停机**：笔记本电池供电且电量 `<= 20%` 时自动通知领队保存检查点并暂停新派发（Linux VPS / 台式机 / WSL2 自动跳过）；重新插电后不会未经你发消息而擅自唤醒继续烧额度。
3. **需要人工介入的场景（`waiting_user` / `blocked`）**：
   - **第三次同案一致异议上调人工**：同一争议链连续第三次触发一致异议时直接暂停并呈交争议卷宗，你在聊天框回复决定后即自动恢复施工。
   - **外部只读路径授权**：领队如需只读访问工作区外的参考目录，会提示你发送一行 `允许读取 /你的外部参考路径`（或 Windows `允许读取 D:\你的外部参考目录`），仅对本会话领队只读生效。
   - **操作系统沙箱权限阻塞（Windows `Win32 5` / Linux `bwrap`）**：当宿主底层沙箱因目录 ACL（Windows `SetNamedSecurityInfoW`）或非特权命名空间限制（Ubuntu AppArmor `bwrap`）无法启动命令行工具时，成员会自动收起命令行工具、先完成所有纯代码/文档阶段后干净停机汇报，绝不盲目重试空耗 Token。可运行 `lt-doctor` 获取针对性修复指引。

## 四、环境诊断、脱敏反馈与历史计划库

```bash
# 1. 环境与宿主兼容性自检（在仓库根目录运行，或直接调用 profile 内的 .bin/lt-doctor）
node bin/lt-doctor.mjs

# 2. 导出零敏感信息泄露的排障诊断报告（供提交 GitHub Issue 使用）
node bin/lt-bugreport.mjs --out lt-bugreport.md

# 3. 查看与复盘外部历史计划库（默认存储于 <DSH_HOME>/leaderteam/plan-archive/，不污染业务仓库）
node scripts/plan-archive.mjs --status
node scripts/plan-archive.mjs --list
node scripts/plan-archive.mjs --retrospect <planId>
node scripts/plan-archive.mjs --clean --older-than-days 30 --dry-run
```
