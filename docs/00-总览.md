# LeaderTeam for DSH (V2.2)：架构总览与设计决定

基于官方 **DeepSeek Harness `0.2.2-rc.1` 与 `0.2.2-rc.5`**（跨平台支持 **Linux & Windows**，`dsh web` / `dsh headless` / 官方 Desktop）。

LeaderTeam V2.2 以**「领队自主执行、双评审异步监督、独立裁断介入纠偏、安全门最高约束、人工处理最终争议」**为核心架构，并通过标准 `dsh.bundle` 插件体系实现跨平台分发：领队、安全门、双评审、独立裁断、串行复核与直属执行模型的路由、推理档位及自动降级链均独立可配（同时支持单环境变量 `Solo-Key` 零网关自举）；领队免同步审批直接派发阶段成员或调用直属执行模型（`team_direct_exec`）；双评审在后台异步监督且绝不将失败请求记为赞同，仅在双方一致异议且与独立裁断达成 2/3 多数时启动正式会商干预，同一实质争议第 3 次触发异议时上调人工；安全门在 `dispatchToolBody` 最后一环执行工作区内确定性直通（零模型调用）与跨界无工具模型审查；全系统配备四桶物理 Token 账本、Linux 层级化 `cgroup` 并发调度、5 小时请求窗口三级节流与笔记本低电量检查点收尾。细节见《[01-配置与接口](01-配置与接口.md)》《[07-按需工具与技能](07-按需工具与技能.md)》《[08-可视化与用量](08-可视化与用量.md)》。

## 3. 关键设计决定

1. **在官方 DSH 内以标准 `dsh.bundle` 插件 + 预设实现，不另造外部壳**：团队会话、子代理消息（兼容 `0.2.2-rc.1` `agent_id` 与 `0.2.2-rc.5` 会话唯一 `agent` 名称映射）与持久化完整复用官方底座，前端编队树与侧栏控制台原生融合。
2. **执行优先，监督异步，干预有门槛，失败不伪造赞同**：消除同步评审阻塞，领队先施工；一侧或两侧评审路由故障时严格挂起待补审而非假装通过；仅在两份真实有效意见一致异议且三方 2/3 多数认可时才暂停干预，同案第 3 次异议直接交还人工决策。
3. **安全门置于工具主体执行前最后一环且绝不妥协**：任何领队决策、双评审结论、独立裁断决议或请求窗口节流均不得跳过安全门；工作区内常规工程动作走确定性快速路径以消除审查延迟与额外 Token 开销。
4. **单次输出限制不等于任务失败**：大模型写长文件触及单轮 `max-tokens` 属于正常现象，直接携带已完成工具清单原位续接，任务粒度完全由真实工程耦合度决定。
5. **配置、运行时状态与源码包目录彻底解耦**：包安装目录（如 `node_modules`）一律按只读对待，托管配置、回滚备份、请求窗口流水与历史计划库全部落盘在 `<DSH_HOME>/leaderteam/` 下。

## 4. 已知边界与处理方式

| 边界项 | 状态说明 | 处理策略 |
|---|---|---|
| `shell` 档位命令隔离粒度 | 依赖官方宿主沙箱（Linux `bwrap` / Windows `workspace-write`）与安全门确定性词法分析，无子目录级内核写隔离 | 处理不可信外部仓库时优先使用 `readonly` / `code` 档位；`direct_exec` 额外受工作区沙箱硬锁约束 |
| 操作系统沙箱初始化受限 | Windows 新目录缺少 `WRITE_DAC`（报 `Win32 5`）或 Ubuntu AppArmor 限制非特权用户命名空间（报 `bwrap` 权限错误）时，成员自动收起命令工具 | 先完成全部非命令行模块后干净停机汇报；运行 `node bin/lt-doctor.mjs` 获取针对性修复命令 |
| 官方客户端版本更新 | 未列入已实机验证白名单（当前为 `0.2.2-rc.1` 与 `0.2.2-rc.5`）的客户端将触发 Fail-Closed 拒绝进入生产运行 | 先用 `lt-doctor --check-host` 预检并在独立环境中跑通全量集成场景后再放行新版本 |
